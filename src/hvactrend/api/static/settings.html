ALERTS → YOUR PHONE (ntfy)

The watchdog (its own scheduled task, every 5 minutes, independent of this server) sends a phone notification when data stops, a controller stops answering or poll cycles keep failing; an all-clear when each one resolves; and a quiet daily check-in each morning. If a check-in ever fails to arrive, the box itself is down.
Notifications go through ntfy, a free push app with no account. Your phone subscribes to a private topic. Anyone who knows the topic can read these alerts, so it is long and random, it is stored with the API keys, and it is shown in full only once, when you generate it. With no topic set, nothing is sent anywhere.
Already made a topic in the ntfy app? Paste it, or its ntfy.sh link, into ntfy topic (phone alerts) under API keys & tokens above, click Save, then Send test message here.

Setting up your phone (about 2 minutes)
  1. Install ntfy from the App Store or Google Play.
  2. Click Generate a private topic above, and keep this page open.
  3. In the app, tap + to subscribe, type the topic exactly as shown, leave the server as ntfy.sh, and subscribe.
  4. Click Send test message. It should arrive within seconds.

UNITS & OCCUPANCY AI context

Ground-truth context for the AI, so anomaly detection stays accurate. Mark a unit Vacant and its idle equipment (fans off, no airflow, off setpoint) is treated as expected — not a fault — while genuine sensor faults / comm loss are still reported. The note is free text the AI reads per unit (e.g. “Floor 8 duct issue when both fans run”). Saved to the database; picked up on the next report.
Occupied hours default to the building schedule. Because start times are staggered per floor (and weekends differ), you can give a unit its own hours — 🔍 Detect from data reads each unit's own Occupancy Status point (or fan speed, ignoring cold-weather freeze circulation) and proposes real hours for you to apply. Days without enough logged coverage are reported as insufficient rather than guessed.

EQUIPMENT & SEQUENCE OF OPERATIONS AI context

What each unit actually is — the AI reads this with every report, so it can judge behavior against real equipment instead of assuming. Setting heating type = none also stops the heat-related checks firing on a cooling-only unit. The sequence of operations is the highest-value field: with it the AI compares observed behavior to designed intent. Everything here is editable at any time — change a value and Save, or clear a field to remove it.
